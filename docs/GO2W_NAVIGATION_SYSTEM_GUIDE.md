## 一、 系统架构与核心机制

在四足轮足机器人（Unitree Go2W）执行长距离室内巡检与导航任务中，楼梯（下长楼梯与上长楼梯）属于典型的高危复杂地形场景。本系统在强化学习端到端平面导航策略（`nav_policy.onnx`）的基础上，通过实车与离线消融实验，确立了**楼梯全地形控制的第一核心主导变量——前瞻点距离（下楼锁存 0.40m，上楼锁存 0.45m）**，并在路径终点引入了**两阶段解耦的原地航向姿态对齐控制（带 60cm 踏步防漂移与 5.0s 超时看门狗保护）**。

实车与离线消融实验表明：

1. **下长楼梯**：是否对深度图进行虚拟坡道重映射，机器人均能平稳下楼；而一旦前瞻距离拉大至 2.0m，深渊断崖避障惩罚压倒远距牵引，必然导致拒止原地打转。锁存 L=0.40m 可实现 100% 平稳直推下楼。
2. **上长楼梯**：面对连续台阶时，若沿用平地大前瞻（1.5m~2.0m），目标被抛到高处或平台导致目标梯度严重稀释，深度相机近距直视阶梯立面突变触发强烈避障刹车/打转；将前瞻点自动收缩为 **L=0.45m**，近端目标牵引梯度牢牢压制避障恐惧，实现坚决平稳爬楼。
3. **终点航向对齐**：采用时序完全解耦的两阶段架构——行进过程（0%~100% 路径长）100% 信任 RL 策略与自适应前瞻，到达终点（< 0.45m）后无缝切入传统死区补偿 P 控制进行原地踏步调姿，辅以 60cm 踏步位移防漂移与 5.0s 超时双重看门狗。

## 二、 核心机理剖析：前瞻点对策略的决定性影响

### 1. 强化学习观测空间中的目标编码原理

导航策略网络（`nav_policy.onnx`）的观测空间中，目标点向量以相对本体坐标系的球坐标归一化形式输入：

```
p_target = [ Δx_b/d, Δy_b/d, Δz_b/d, log(d + 1) ],   d = sqrt(Δx_b² + Δy_b² + Δz_b²)
```

在强化学习多任务奖励函数中，存在两个对立的驱动力：
- **目标到达奖励（Goal-reaching Reward）**：驱使机器人缩短与 Carrot 点的欧氏距离；
- **安全与避障惩罚（Collision/Cliff Avoidance Penalty）**：当深度图检测到近身存在断崖、陡坡或不可通行台阶时，惩罚前向速度，激励减速转向。

### 2. 短前瞻点（L = 0.40m）为什么能坚决下楼？

- **近端牵引梯度占绝对优势**：当 L = 0.40m 时，3D 目标点紧贴机器人前方台阶下方（Δx_b ≈ 0.4m, Δz_b ≈ −0.3m），d ≈ 0.5m，log(d+1) ≈ 0.41。
- **压倒断崖恐惧**：此时目标点在物理空间上处于“下一踏步”的落脚点范围内。策略网络判定目标为触手可及的紧迫任务，近端目标牵引奖励的梯度大幅压倒了相机所见阶梯断崖的避障惩罚。
- **输出动力学**：策略网络第一步即输出坚决的前进指令（v_x ≈ 0.50 ~ 0.55 m/s），航向角速度近乎为零（|ω_z| ≤ 0.15 rad/s），机器人直接踏下阶梯。

### 3. 长前瞻点（L = 2.0m）为什么绝对不下楼？

- **远端牵引衰减，避障占据统治地位**：当 L = 2.0m 时，d ≈ 2.5m，log(d+1) ≈ 1.25。目标点在遥远的下方空间。
- **视差深渊被判定为绝壁死胡同**：此时机器人眼前的相机俯视画面呈现大面积阶梯边缘与视差空洞，而两米外的目标无法提供足够的近距冲力。策略网络的碰撞评估模块将楼梯断崖判定为“前方存在严重垂直障碍/悬崖断头路”。
- **避障逃逸触发打转**：为了规避坠落和碰撞，网络激活逃逸策略，前向速度迅速归零并饱和输出反向角速度（|ω_z| → 1.0 rad/s），导致机器人在楼梯口原地急转或倒车后退。

### 4. 深度重映射的真实定位

- **消融结论**：实验证明，深度重映射并非“能否下楼”的必要条件。在 L=0.40m 下，纯原始深度图同样能够 100% 顺利下楼；在 L=2.0m 下，重映射深度图也无法挽救拒止。
- **辅助价值**：深度重映射将视差空洞与阶梯立面平滑为虚拟斜坡，其主要贡献在于进一步收敛航向抖动（将 |ω_z| 从 0.16 降低至 0.09 rad/s），并抑制两旁反光栏杆对视觉特征的扰动。因此，深度重映射作为可选的平滑增强算子，默认关闭即可实现极简无开销直通。

## 三、 关键技术模块详解

### 1. 3D 路径双向坡度门控 (StairsSlopeGate)

- **触发原理**：沿全局 3D 路径在前向评估窗口（默认 1.2m）计算高程变化 Δz 与投影斜率 k = Δz / Δs_2d。
- **下楼进入判定**：当 k < −0.20（坡度下倾 >11.5°）且 Δz < −0.15m（单阶落差）时，提前约 0.5m 触发 `is_descending_stairs = True`。
- **上楼进入判定**：当 k ≥ +0.20（坡度上扬 >11.5°）且 Δz ≥ +0.15m（单阶爬升）时，提前约 0.5m 触发 `is_ascending_stairs = True`。
- **双向空间迟滞退出**：
  - 下楼退出：未来路径坡度回平（k > −0.10）且机器人平地行走超过 0.6m（`exit_dist_threshold`），平稳释放下楼状态；
  - 上楼退出：未来路径坡度回平（k < +0.10）且机器人平地行走超过 0.6m，平稳释放上楼状态。
- **终点防死锁机制**：当剩余路径不足 0.3m 且末端无陡坡时，自动平滑释放楼梯状态，恢复平地防卡滞监测。
- **平地状态零影响保证**：平地时（|k| < 0.10），上下楼状态均为 False，100% 保持原有弯道自适应。

### 2. 楼梯前瞻锁存（下楼 0.40m / 上楼 0.45m）

- **平地前瞻**：默认支持 0.5m ~ 2.0m 弯道曲率自适应（直道 2.0m 巡航，直角转弯 0.5m 贴边）；
- **下楼前瞻锁存 (0.40m)**：强制锁存为 0.40m（`stair_lookahead_dist`），压制平地长前瞻，近端目标牵引梯度牢牢压制视觉深渊恐惧；
- **上楼前瞻锁存 (0.45m)**：强制锁存为 0.45m（`stair_up_lookahead_dist`），压制平地门洞误收缩，避免目标被抛射过高产生梯度稀释，确保坚决直推爬梯。

### 3. 防后转安全护栏与爬坡卡滞保护

- **爬坡卡滞豁免**：上下楼过程中，机器人行进速度通常较慢，控制器周期性重置 `blocked_detector`，彻底避免爬长楼梯缓慢误判为停滞报错；
- **途中下楼纠偏（距离终点 > 0.60m）**：仅在目标真正落入身后（dx_b < −0.15m）时介入纠偏，杜绝转弯入梯口正常偏角时的误钳位；
- **终点收敛（距离终点 ≤ 0.60m）**：护栏自动退让，允许目标自然归零，引导平稳制动。

### 4. 速度控制与终点精准刹停

- **彻底移除 0.35m/s 硬限制**：允许策略网络自由减速到 0.0 m/s 刹停；
- **单向非负防倒车边界**：上下楼时均强制 v_x ≥ 0.0，杜绝阶梯上挂倒档；
- **角速度限幅**：ω_z ∈ [−0.5, 0.5] rad/s，抑制台阶上剧烈甩尾擦碰扶手与立柱；
- **真实到达判定阈值**：`segment_arrive_threshold = 0.45m`（支持 `--arrive-thresh` 配置，原地漂移/放弃转身容差 `terminal_align_abort_dist = 0.60m`）。进入终点半径立即发布 `cmd_vel = 0`，清空路径，进入终点航向对齐或直接完成状态转移（`GOAL_REACHED -> IDLE`）。

### 5. 终点航向与姿态对齐控制（Terminal Heading & Pose Alignment）

#### 5.1 两阶段完全时序解耦设计

- **过程阶段（0% ~ 100% 路径长）**：100% 由 SRU 视觉策略网络与自适应前瞻模块接管，过程中**严禁**强加任何横向转向力矩，确保动态避障、走廊通行、上下楼梯等优秀的地形机动性不受破坏；
- **终点阶段（距离终点 < 0.45m）**：仅在平面距离到达终点阈值后触发。若路径最后一个点（`poses[-1]`）携带有效四元数朝向，系统无缝切入传统死区补偿 P 控制进行原地踏步调姿，外部状态平稳保持为 `RUNNING`。

#### 5.2 楼梯/陡坡自转禁绝保护（Stair/Slope Spin Guard）

若机器人到点时坡度门控指示当前仍处于楼梯上（`is_stair_down == True` 或 `is_stair_up == True`），**严格禁止原地大幅度旋转**！必须直接以当前行进姿态刹车就地完成，防止四足在台阶立面打滑踩空跌落。

#### 5.3 分段非线性控制律（带摩擦死区补偿与限幅的 P 控制器）

Unitree Go2W 在静止状态下进行原地踏步自转时，足底与地面存在静摩擦力矩。若直接使用线性 P 控制，在小误差区间输出的极小角速度将无法克服静摩擦，导致机器狗原地踏步震颤而不旋转；而在大误差区间若速度过大，又会产生剧烈侧晃。

因此，采用如下分段非线性控制律：

```
ω_z = 0.0,                                    if |Δθ| ≤ θ_tol
ω_z = sgn(Δθ) · clamp( |Δθ|·K_p + ω_deadband, ω_min, ω_max ),   if |Δθ| > θ_tol
```

推荐工程参数（`constants.py` 默认值）：

| 参数 | 变量名 / 默认值 | 物理意义与工程取值依据 |
|---|---|---|
| 对齐容差阈值 | `terminal_heading_tol = 0.26 rad`（≈15°） | 允许的最终对齐误差。四足踏步不宜低于 3°（避免因步态离散产生微震），5° 是工程平衡点；现行取 15° |
| 比例增益 | `terminal_heading_kp = 1.2` | 航向误差比例响应增益 |
| 摩擦死区补偿 | `terminal_heading_deadband = 0.12 rad/s` | 确保进入转动时立刻给予基础自转扭矩，利落转动 |
| 最小角速度钳位 | `terminal_heading_min_vel = 0.15 rad/s` | 防止旋转末端角速度过小卡滞 |
| 最大角速度钳位 | `terminal_heading_max_vel = 0.45 rad/s` | 限制最大自转速度，防止机身晃动或踏空 |
| 对齐超时保护 | `terminal_heading_timeout = 5.0 s` | 原地对齐最大允许耗时，防打滑或卡死看门狗 |
| 平滑低通滤波 | `LOW_PASS_FILTER_COEF[2] = 0.5` | 沿用已有指令低通滤波器，加减速平滑不顿挫 |
| 踏步漂移容差 | `terminal_heading_drift_tol = 0.40 m` | 四足原地踏步防漂移保护线 |
| 稳定驻留帧数 | `terminal_heading_stable_frames = 2` | 连续满足容差才判定完成，避免动态过冲假象 |

输出指令由低通滤波平滑处理（α = 0.5），输出平顺，杜绝机身剧烈侧晃。

#### 5.4 上层 Path 朝向信息与坐标系解析

上层通过 `/nav/global_path`（或配置的 `path_topic`）发布的类型是标准 ROS 2 `nav_msgs/msg/Path`，包含 `poses: PoseStamped[]`，每个点含 `pose.position (x,y,z)` 与 `pose.orientation (x,y,z,w)`。

**解析判定准则**（`rl_nav_controller.py` 已有逻辑）：

```python
final_q = path_msg.poses[-1].pose.orientation
norm_sq = final_q.x**2 + final_q.y**2 + final_q.z**2 + final_q.w**2
terminal_yaw = None
if norm_sq > 0.5:  # 有效四元数（已归一化，非未初始化的 [0,0,0,0]）
    terminal_yaw = atan2(2.0*(final_q.w*final_q.z + final_q.x*final_q.y),
                        1.0 - 2.0*(final_q.y**2 + final_q.z**2))
```

- **情况 A（有效朝向）**：`norm_sq > 0.5`，上层显式指定了终点姿态，成功提取到 `terminal_yaw`。
- **情况 B（无朝向需求）**：若上层只填坐标、未填姿态导致四元数全为 0（`norm_sq <= 0.5`），则 `terminal_yaw = None`。此时控制器**直接跳过对齐阶段**，到达位置立即完成。

**坐标系基准与转换流**：
- 上层路径的位姿定义在 `path_msg.header.frame_id`（通常为全局地图系 `'map'` 或 `'world'`）；
- 机器狗当前位姿 `robot_pos_w, robot_orientation_w`（由机载激光 SLAM 或里程计解算）同样位于该系；
- 当前朝向解算：若当前全局四元数为 [w, x, y, z]，机器狗在全局系的实际偏航角为
  `θ_robot = atan2(2.0·(w·z + x·y), 1.0 − 2.0·(y² + z²))`；
- 航向误差角 Δθ：在全局系下做角度差，并通过环形解缠绕映射至 [−π, π]：
  `Δθ = atan2(sin(θ_target − θ_robot), cos(θ_target − θ_robot))`；
- 控制指令输出系：误差 Δθ 算出的角速度 ω_z 输出到 `/cmd_vel`（`Twist`），属于机器狗机体坐标系（`base_link`）的自转速度，线速度 v_x = 0.0, v_y = 0.0。

#### 5.5 五重安全与异常防护机制

1. **四元数未配置直接跳过（Graceful Fallback）**：若 `path_tracker.terminal_yaw is None`，则说明上层无需对齐朝向。位置一旦满足 < 0.45m，立刻原路退出并报 `GOAL_REACHED`。
2. **楼梯/陡坡自转禁绝保护**：若位置到达时坡度门控显示当前仍处于楼梯上，严格禁止原地大幅度旋转，直接以当前姿态就地刹车完成。
3. **超时看门狗保护**：开始执行对齐时记录 `heading_align_start_time = now()`。若超过 5.0s 仍未进入容差范围，强制输出 0 速度并中止对齐，记录警告日志并流转至 `GOAL_REACHED`，防止无限原地踏步耗尽电池。
4. **踏步位置漂移保护**：四足原地踏步可能产生轻微平移。每周期检测当前位置与终点坐标的距离：若漂移量超过 0.60m（`terminal_align_abort_dist`），立即终止旋转并刹停，防止漂出安全通行区。
5. **稳定驻留确认**：连续满足 |Δθ| ≤ θ_tol 达到 0.2s（约 2~3 个控制周期）才正式判定完成，避免瞬时穿过目标朝向的动态过冲假象。

#### 5.6 实施路线（供参考）

`adaptive_path_tracker.py` 中 `AdaptivePathSegmentTracker.get_terminal_pose()` 已提供 `(terminal_pt, terminal_yaw)` 一键获取。控制器在 `generate_cmd_vel()` 中的到达判定分支已完成对齐状态机与 `_handle_terminal_heading_alignment()` 分支，`start_nav.sh` 默认 `ENABLE_HEADING_ALIGN=true`、`HEADING_TOL=0.26`。单元测试：`tests/test_terminal_heading_alignment.py`（含无朝向直接完成、正反向最短转角、死区与限幅、收敛终止、超时看门狗、楼梯上保护）。

## 五、 快速部署与操作参考

### 1. 同步与构建

```bash
./scripts/sync_stairs_to_go2w.sh <ROBOT_IP>
```

### 2. 启动命令

```bash
ssh agile@<ROBOT_IP>
cd ~/go2w_nav_ros2_ws

# 推荐标准模式: 弯道曲率自适应 + 楼梯感知 + 终点姿态对齐
./start_nav.sh --curv-only

# 或使用专用启动脚本
./start_nav_stairs.sh --curv-only

# 诊断监控
ros2 topic echo /nav/is_descending_stairs
ros2 topic echo /nav/is_ascending_stairs
```

> 注：`start_nav.sh` 默认已是 `curvature_only` 模式，`--curv-only` 可省略；显式写出便于审计。

### 3. 关键启动参数表

| 参数名称 | 环境变量 / CLI 选项 | 默认值 | 作用说明 |
| :--- | :--- | :--- | :--- |
| 到达判定阈值 | `--arrive-thresh` | `0.45m` | 终点到达距离判定线（进入 0.45m 半径触发制动并进入对齐或完成） |
| 终点航向对齐 | `--heading-align` / `--no-heading-align` | 开启 (true) | 是否在到达终点坐标后执行原地踏步姿态对齐 |
| 航向对齐容差 | `--heading-tol` | `0.26 rad`（≈15°） | 航向对齐收敛判定容差（连续稳定 2 帧即完成） |
| 踏步漂移容差 | `terminal_heading_drift_tol` | `0.40m`（40cm） | 原地对齐防漂移保护线，四足微滑越界即强制刹停完成 |
| 对齐超时保护 | `terminal_heading_timeout` | `5.0s` | 原地对齐最大允许耗时看门狗，防原地无限打转 |
| 下楼前瞻距离 | `--stair-lookahead` | `0.40m` | 下坡锁存前瞻，策略近距目标牵引最优响应点 |
| 上楼前瞻距离 | `--stair-up-lookahead` | `0.45m` | 上坡锁存前瞻，抑制目标梯度稀释，坚决冲坡爬梯 |
| 下楼坡度阈值 | `--stair-slope` | `-0.20` | 触发下楼门控斜率阈值（提前约 0.5m 判定，平滑减速入梯） |
| 上楼坡度阈值 | `--stair-up-slope` | `+0.20` | 触发上楼门控斜率阈值（提前约 0.5m 判定，坚决稳步爬梯） |
| 楼梯深度重映射 | `--remapping` / `--no-remapping` | 关闭 (raw) | 是否开启虚拟斜坡深度重映射（默认关闭：纯原始深度图） |
| 下楼最低限速 | `--stair-min-vel` | `0.0m/s` | 保底推进速度（设为 0.0，杜绝强制冲撞） |
| 扶手防撞钳位 | `--stair-side-clamp` | `0.50m` | 两侧扶手栏杆最小保护距离（重映射模式下生效） |
| 起缩偏角门限 | `turn_angle_low` | `20.0°` | 路径偏角 ≤ 20° 时保持 2.0m 前瞻，走廊轻晃不减速 |
| 全缩偏角门限 | `turn_angle_high` | `50.0°` | 路径偏角 ≥ 50°（直角弯及转入梯口）前瞻完全收缩至 0.5m |
| 前瞻评估窗口 | `adaptive_window_dist` | `1.6m` | 评估前瞻窗口，提前约 0.8m 捕捉急转弯与梯口 |
| 自适应模式 | `--mode` | `curvature_only` | 默认 `curvature_only`，规避狭长走廊墙壁视觉误触发 |
| 终点朝向对齐 | `--heading-align` / `--no-heading-align` | 开启 | 到达终点后是否执行原地踏步姿态对齐 |
| 航向对齐容差 | `--heading-tol` | `0.26 rad`（≈15°） | 航向对齐收敛判定容差 |
| 航向对齐超时 | `--heading-timeout` | `5.0s` | 原地对齐最大允许耗时 |
| 航向对齐最大角速度 | `--heading-max-vel` | `0.45 rad/s` | 对齐阶段最大自转角速度 |
| 航向对齐最小角速度 | `--heading-min-vel` | `0.15 rad/s` | 对齐阶段最小自转角速度（克服静摩擦） |
