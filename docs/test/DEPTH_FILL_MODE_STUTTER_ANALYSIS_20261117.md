> 数据：2026-11-10 两段 RealSense 门/楼梯路线会话
> - `session_20261110_145214_realsense`（note `RS run1`，旧预处理：无效像元 → `min_depth`）
> - `session_20261110_145750_realsense`（note `RS run3 v2`，新预处理：无效像元 → 最近有效值）
>
> **处置（2026-11-17）**：V2 改动已保存到 `sru-robot-deployment` 的分支 `exp/depth-fill-v2`（commit `b365665`），工作树已回退到旧的 `min_depth` 填充；后续前瞻参数测试使用 `min` 基线。

## 0. 结论（先看这里）

### 一句话结论

**这次改动让实机表现变差了，变差的是“偏航摆动”而不是速度：平地上策略的 `|cmd_wz|` 均值 0.277 → 0.440（+59%），打到 ±1 饱和的帧占比 2.8% → 25.6%（9 倍），实际偏航角速度 0.272 → 0.357 rad/s，航向误差中位数 13.0° → 21.7°。差异集中在三段平地窗口（0–5 m、20–25 m、30–36 m），中间 5–20 m 两段基本一致。原因是 V2 把“空洞”读成“远/开阔”，而策略是在旧填充下训练的。**

两次运行的目标点相距 0.12 m、起点相距 0.25 m、路径 34.0 vs 33.6 m——这已经足够算匹配对比；平地停顿本身两次都有（7 vs 11 次），不是本次的特例。所以判据不能是“有没有停”，只能是“同样该直行的平地上，车摆不摆、快不快”。图像更平滑只是排除了一个机制（输入抖动），不是结论本身。

### 分项

1. **任务时间窗（由 `/cmd_vel` 非零推断）**

   | 会话 | 任务段 | 时长/里程 | 遥控返程段（cmd 全零、odom 仍在动） |
   |---|---|---|---|
   | 旧（min） | 14:53:11.3 – 14:54:36.2 | 85.0 s / 33.8 m | 14:54:36.5 – 14:56:15.6（99.1 s / 36.9 m） |
   | 新（nearest） | 14:57:55.4 – 14:59:29.3 | 93.8 s / 35.3 m | 14:59:29.6 – 15:00:40.7（71.2 s / 36.1 m） |

   两段任务的航线、经过的时间轴几乎重合（同一门/楼梯环线），可以直接对比。

2. **新会话确实更“卡”，而且卡在平地**：平地速度纹波 std 0.081 → 0.121（+49%），`|cmd_wz|` 均值 0.277 → 0.440（+59%），平地 `|cmd_wz|>0.7` 占比 2.8% → 25.6%（9 倍，`cmd_wz` 频繁打到 ±1 饱和），航向误差中位数 13.0° → 21.7°，停→走 5.65 → 7.67 次/分，硬减速 7 → 11 次，`|加速度|` p95 0.573 → 0.804，并出现 −0.54 m/s 的倒车指令（旧最低 −0.09）。

3. **但“深度输入变差/变抖”这个假设不成立。** 同一批原始帧上复算：nearest 填充让 64×40 输入在空间上更平滑（`|d-mean3×3|` 0.218 → 0.127，孤立近点 6.2 → 0.68 px/帧，3×3 深度极差 1.06 → 0.69 m），在时间上也更稳定（逐帧 `|Δ|` 0.462 → 0.406 m，p95 2.41 → 2.06 m）。它没有往策略输入里注入新的抖动。

4. **真正被改变的是输入的“语义”**：无效像元从“最近（0.15 m）”变成“最近有效值”。假近单元 5.8–6.5% → 0–0.3%；空洞很大时整片区域会从“0.15 m 近墙”翻成“2–4 m 开阔”（见 `depth_v0_v2_same_frame.png` 的 idx 315，59% 空洞帧）。

5. **反事实（同一状态、各自 LSTM、只换填充）**：VAE 嵌入余弦 0.927–0.929、相对 L2 差 37%；策略偏航指令平均变化 0.080 rad/s、p95 0.31–0.36 rad/s（相当于平地 `|cmd_wz|` 中位数的 1/3 到 1 倍），`vx` 变化 p95 0.11–0.14 m/s。**换填充对策略是一次真实的输入分布迁移**——而策略是在旧填充下训练/调出来的。

6. **平地停顿本身不是判据**：两次运行都有（7 vs 11 次），典型事件都是“指令满速、车不动”（t≈4.8–5.9 s：`cmd_vx` 1.31–1.38，实际速度 0.02–0.08 m/s，深度 near=0，Livox 前向 1.2 m）——策略在让它前进，是执行层/物理接触没动，与深度预处理无关。所以本次要解释的是“该顺行时的摆动”，不是“有没有停”。

7. **要坐实因果，仍建议同日 A/B（各 3–5 次）**。本分析能说明的是：起点/目标/路径基本匹配、差异只出现在该顺行的平地窗口、且反事实把偏航指令移动了同量级的量——三条证据指向同一结论；但单次对比给不出置信区间，操作手、电池、路径微差这些因素没有被随机化掉。

| 会话 | 任务段 | 任务里程 | 平均速度 | 返程平均速度 |
|---|---|---|---|---|
| 旧（min） | 14:53:11.289 – 14:54:36.247 | 33.8 m | 0.398 m/s | 0.372 m/s |
| 新（nearest） | 14:57:55.446 – 14:59:29.275 | 35.3 m | 0.376 m/s | 0.506 m/s |

## 3. 图像处理的改动实际做了什么

四种填充变体在 `PREPROCESSING_ABLATION_V0_V5_20261110.md` 里已有图像级结论；这里补充**时间维度**和**与策略的距离**。

### 3.1 更好，不是更差

| 指标（64×40 输入） | 旧（min） | 新（nearest） |
|---|---:|---:|
| near(<0.3 m) 占比（全段） | 5.75% | **0.12%** |
| 空间粗糙度 \|d−mean3×3\| | 0.218 | **0.127** |
| 孤立近点（自身<0.35、8 邻域全>0.9）px/帧 | 6.20 | **0.68** |
| 3×3 深度极差 均值 / p95 | 1.06 / 5.64 | **0.69 / 3.20** |
| 中心 ROI 最小值 均值（全段） | 0.143 | **0.675** |
| 逐帧 \|Δgrid\|（同一批原始帧，平地） | 0.462 | **0.406** |
| 逐帧 \|Δgrid\| p95 | 2.41 | **2.06** |

注意：`depth_center_min` 的**时间 std** 会从 0.23 升到 0.50，这**不是**噪声变大——旧填充把无效像元钉死在 0.15 m，`min` 自然“稳定”；去掉这个钳位后最小值才随真实几何变化。图像本身的时间稳定性是变好的（上表最后两行）。

### 3.2 语义变化：空洞区域会由“近”翻成“远”

`depth_v0_v2_same_frame.png` 用同一批原始帧对比 V0/V2。差值主要在空洞边缘（idx 36、120），但**在 59% 空洞的帧（idx 315）上是整片的米级差异**：V0 把左侧无效区填成 0.15–0.5 m（伪“近墙”），V2 用最近有效像素把它填成 2–4 m（“开阔”）。

这就是 V2 的双面性：空洞被真实表面包围时更准；**当近处物体本身成片无效（反光、纯黑、低纹理）时，它会被填成远处的背景**，策略看到的是“开阔”。文档 §1.2 担心的“过于大胆”正是这种情况。

### 3.3 对策略输入的影响（反事实）

`scripts/depth_benchmark/fill_mode_counterfactual.py`：从两段会话的 16-bit 原始深度按控制器同一套规则重建 64×40，分别跑 VAE 与策略（TorchScript，权重与部署 ONNX 一致；`obs=2576`，即无 heading 版本）。两条分支各自维护 LSTM，状态量（body 速度、重力、`last_action`、目标向量）由日志重建并逐帧对齐。

| 量 | 旧会话 | 新会话 |
|---|---:|---:|
| VAE 嵌入 余弦均值（最小） | 0.929（0.769） | 0.927（0.692） |
| VAE 嵌入 相对 L2 差 | 36.9% | 37.5% |
| \|Δvx\| 均值 / p95（tanh 输出） | 0.034 / 0.112 | 0.038 / 0.139 |
| \|Δwz\| 均值 / p95 | **0.080 / 0.311** | **0.081 / 0.361** |
| 符号一致率 vx / wz | 97.6% / 97.3% | 98.3% / 96.3% |
| 逐帧抖动（cmd 步长） vx / wz | 0.323 / 0.094 | 0.321 / 0.099 |

两点：

- **偏航通道被改得最多**：同状态下 `|Δwz|` 平均 0.08 rad/s、p95 0.31–0.36 rad/s，相当于现场指令量级的三分之一到一整倍。这与观测到的“平地 `cmd_wz` 频繁饱和、航向误差变大”方向一致。
- **没有新增抖动**：逐帧步长两种填充几乎相同（0.323 vs 0.321 / 0.094 vs 0.099）。“填充注入噪声”可以排除。

> 局限：回放对 `vx` 的相关性 0.59–0.69、对 `wz` 接近 0——严格回放还缺 `raw_action`/`target_yaw_w`/初始 LSTM 状态（见方案 §2.2）。因此**绝对动作**不可信，只有“同一状态下两分支的差（Δ）”可用。

## 4. 与填充无关的部分

1. **“指令满速、车不动”的硬减速**：新会话 11 次、旧 7 次。抽检新会话的每次事件，`cmd_vx` 都在 0.26–1.38，深度 `near_ratio=0`，Livox 前向 1.19–1.30 m——策略没有刹车，是机体没动。例：t=4.8–5.9 s 速度 0.08→0.02→0.04→0.69。这类事件更像执行层（bridge / Unitree 底层步态）或物理接触（机体 z 由 0.024 掉到 0.007 再回来），与深度预处理无关。
2. **平地上“转不动/转过头”的极限环**：t≈5.9–8.0 s `cmd_wz` 连续 ≥0.96 直至 +1.0，机器人航向 6.8°→75°→41°，随后 t≈9.1–9.7 s 翻到 −0.85/−0.93。同段旧会话 `cmd_wz` 在 −0.34…+0.46 之间。这一段是新会话“平地卡顿”的主体，也是最可能由策略行为改变造成的部分。
3. **深度空洞突增**：新会话 t≈80 s 有一帧空洞比例 59%（旧会话最大 15%），随后 `cmd_wz` 出现 −0.81/−0.95。这是真实的传感器事件（正对着低纹理/反光面），不是填充造成的，但 V2 在这种帧上的“翻成开阔”会放大它的影响。
4. **同一次部署里还有几处未提交的改动**（不影响本次运行，但做 A/B 时要钉住）：
   - `rl_nav_controller.launch.py` 的 `min_depth` 默认 0.15 → 0.25（`start_nav.sh` 显式传 0.15，所以本次不受影响；走 launch 的 `start_nav_custom.sh` 会受影响）；
   - `constants.ARRIVE_GOAL_THRESHOLD` 0.20 → 0.75（只用于单目标模式与路点序列；路径跟随用 `segment_arrive_threshold=0.20`，本次不受影响）；
   - `rl_nav_controller_adaptive.launch.py` 的 `segment_arrive_threshold` 默认 0.20 → 0.15（`start_nav.sh` 显式传 0.20）；
   - `path_tracker.py` 删掉了 `has_path/realign_to_robot/frame_id`，但 `rl_nav_controller.py` 仍在调用——stairs/adaptive 节点用的是未改动的 `AdaptivePathSegmentTracker`，所以本次没事；**如果直接跑基础版 `rl_nav_controller.py` 会 AttributeError**。

## 6. 建议

**第一步（当天可做，1 小时）— 同日 A/B 确认归因**

同一条路线、同一目标/路径，`min` 与 `nearest` 交错各 3–5 次（A B B A）：

```bash
export DEPTH_FILL_MODE=min      # 或 nearest
./start_nav.sh
```

logger 端要同步：控制器用 `min` 时给 `door_diagnostic_logger.py` 加 `--depth-fill-mode min`，否则记录的 64×40 与策略输入不一致。

每次跑完用同一张表对比（字段定义见脚本 docstring）：

```bash
python3 scripts/analyze_motion_stutter.py \
  --session door_diagnostics/<新会话A> --session door_diagnostics/<新会话B> \
  --out door_diagnostics/analysis_ab_<日期>
```

看四个判据：平地速度纹波 std、平地 `|cmd_wz|` p50/p90、`|cmd_wz|>0.7` 占比、停→走 次/分钟。若 `min` 组的这四项都回到 0.08 / 0.23 / 0.03 / 5.6 附近，则归因成立。

**第二步 — 如果确认是填充带来的行为迁移，二选一**

- **保守**：默认改回 `min`（一行 env 或把 `depth_fill_mode` 默认值改回 `min`），把 V2 留作后续训练的实验项；
- **正确**：保留 V2，但用 V2 的输入重训/微调策略（至少先做方案 §2 的 L1 动作级回放，把 `raw_action`、`target_yaw_w`、`last_action` 补进日志），否则策略一直在分布外工作。

如果暂时两者都做不了，可以试**折中填充**：`far_mask` 仍置 0；`close_mask` 用最近有效值，但把“盲区/底部近地 ROI”保留 `min_depth` 或按距离下限钳位（例如填充值不低于 `nearest_valid − 0.3 m`），这样既减少假近、又不会被远处的背景填进近处空洞。

**第三步 — 单独查“满速不动”**

它和相机无关，但在新会话里更频繁。建议在 bridge 侧加日志：`/cmd_vel` 到达时间戳、下发到底层的频率、底层实际速度；确认是命令节流、看门狗，还是机体物理卡住（t≈5 s 处机体 z 掉到 0.007）。

**第四步 — 补日志字段**
